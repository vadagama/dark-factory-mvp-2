# ADR-0003: Модель домена ядра

## Статус

Принято (инициализация репозитория, 2026-09-22).

## Основание

Notion v4: [«Ядро Dark Factory» (стр. 2)](../sources/notion-v4/02-core.md),
[«Рабочие окружения и параллельное выполнение» (стр. 6)](../sources/notion-v4/06-workspaces-parallelism.md),
[«Хранение состояния, CLI и будущая Console» (стр. 10)](../sources/notion-v4/10-state-cli-console.md);
анализ §5; must-keep 1–3.

## Контекст

Нужна минимальная, детерминированная доменная модель конвейера: что такое работа
(Change/Run), исполнение (StageRun/Attempt), результаты (Artifact), согласование
(Question/Decision) и внешние действия.

## Решение

- **Минимальные понятия**: `Change` (изменение продукта), `Run` (прогон процесса),
  `StageRun` (исполнение этапа), `Attempt` (агентная попытка в DSH), `Artifact`,
  `Workspace`, `ExternalOperation`, `Question`/`Decision` (в т.ч. gate decision).
- **Сущности «агент-профессия» нет** — роли (Review, QA, …) являются конфигурациями
  (см. ADR-0004), а не доменными объектами.
- **Процесс — граф этапов + ограниченные циклы доработки**; `StageRun` несёт `generation`
  (номер поколения при повторных попытках этапа).
- **Состояния `StageRun`**: `pending → ready → running → (waiting_input | reconciling) →
  evaluating → accepted | blocked | failed | cancelled`.
- **Состояния `Run`**: `created, running, waiting, succeeded, failed, cancelled`.
- **Исполнители этапов**: `harness` (агентная попытка → DSH), `command`
  (детерминированная команда), `integration` (внешняя интеграция). Гейт — внутри ядра,
  отдельным исполнителем не является.
- **`GateResult` не выбирает следующий этап**: гейт выносит вердикт по результату этапа;
  выбор следующего этапа — у ядра по графу процесса.
- **retry ≠ rework**: `retry.max_attempts` — повторы той же попытки при технических сбоях;
  `rework.max_cycles` — цикл доработки (новая Attempt по находкам гейта) с лимитом циклов.
- **Автооткат внешних действий запрещён**: откат выполняется компенсацией/оператором,
  не автоматикой ядра.
- **Event sourcing не нужен**: журнал событий — компактный, в SQLite (ADR-0002).

## Последствия

- Модель компактна и проверяема; рост сложности процесса — через декларации (ADR-0004).
- Лимиты retry/rework обязательны в конфигурации этапов — защита от бесконечных циклов.
- Переходы состояний фиксируются контрактами в `@dark-factory/contracts` (zod).
