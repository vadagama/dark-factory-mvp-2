# ADR-0011: Безопасность и доверие

## Статус

Принято (инициализация репозитория, 2026-09-22).

## Основание

Notion v4: [«Контракт с DSH» (стр. 4)](../sources/notion-v4/04-dsh-contract.md),
[«Модульность, декларативность и плагинная архитектура фабрики» (стр. 12)](../sources/notion-v4/12-plugins.md);
анализ §5; must-keep 5, 7, 10.

## Контекст

Фабрика исполняет LLM-агентов с доступом к коду и окружениям. Нужна модель доверия:
кто что может, где границы, и почему агентная попытка не может слить код в production.

## Решение

- **Machine-аккаунт для фабрики**: все действия в продуктовых репозиториях — от
  идентифицируемого сервисного аккаунта, не персонального.
- **Роли allow/deny + write_scopes**: роль попытки задаёт белый/чёрный список действий
  и области записи; **этап сужает разрешения, не расширяет** (ADR-0004).
- **Неповеренный продуктовый слой**: код/инструкции продуктового репозитория исполняются
  в ограниченном окружении попытки (workspace-профиль), с выдачей секретов по необходимости.
- **Секреты вне git**: в декларациях — только ссылки (env/секрет-хранилище); значения
  подставляются в момент исполнения и не попадают в логи.
- **Redaction**: артефакты и отчёты попыток проходят фильтрацию секретов до регистрации.
- **DSH без токенов merge/production**: агентные попытки не получают полномочий слияния
  и доставки (ADR-0006).
- **TypeScript-интерфейс — не граница безопасности**: изоляция обеспечивается процессами/
  окружениями; недоверенные плагины — вне процесса ядра (ADR-0010).
- **Полномочия — минимально необходимые**: composition root выдаёт пересечение
  запрошенного и допустимого (ADR-0010).

## Последствия

- Компрометация попытки не даёт доступа к merge/production и секретам вне её скоупа.
- Проверка секретов в гит-гейтах обязательна (pre-commit/CI), ссылки без значений
  валидируются схемой.
