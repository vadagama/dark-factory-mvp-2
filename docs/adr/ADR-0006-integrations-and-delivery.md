# ADR-0006: Интеграции и доставка

## Статус

Принято (инициализация репозитория, 2026-09-22).

## Основание

Notion v4: [«Git/VCS и доставка через CI/CD» (стр. 8)](../sources/notion-v4/08-git-vcs-delivery.md),
[«Проверки, гейты и цикл доработки» (стр. 7)](../sources/notion-v4/07-gates-and-rework.md);
анализ §4 (Q4), §5; must-keep 8, 10. Решение Q4 утверждено 2026-09-22:
GitHub-first, VCS Provider-адаптер с поддержкой GitHub и GitLab.

## Контекст

Фабрика работает с продуктовыми репозиториями, CI и окружениями доставки. Нужны границы:
что фабрика делает сама, что требует человека, и почему автономный merge допустим.

## Решение

- **Четыре границы адаптеров** (модули, не сервисы): Git (локальный), VCS Provider
  (платформа), CI/CD, Deployment. Ядро не знает платформ — только контракты адаптеров.
- **Локальные проверки — primary**, CI — доставка результатов и независимое
  подтверждение; фабрика не ждёт CI как единственного источника истины.
- **Одна integration-ветка на Change + одна MR**; ветки попыток —
  `factory/<change>/<stage>/attempt-N` (см. ADR-0008/hld).
- **Передача кода DSH ≠ merge**: снимок попытки попадает в git только через
  контролируемую интеграцию ядра.
- **Merge gate ≠ delivery gate**: слияние и поставка — разные решения с разными
  политиками; `pipeline: succeeded ≠ deployment: healthy`.
- **`DeliveryAdapter`**: операции `start/observe/cancel`; статусы `merged / deployed /
  verified` отслеживаются раздельно.
- **Автономный merge — только при 5 условиях**: (1) актуальный результат принят гейтом;
  (2) проверки зелёные на текущем commit; (3) правила защищённой ветки соблюдены;
  (4) нет блокирующих findings; (5) политика риска разрешает (см. ADR-0012, Q9).
- **DSH не выдаются токены merge/production**: слияние и доставка — через адаптеры ядра,
  а не через агентные попытки.
- **Последовательная очередь интеграции**: интеграция Change'ей выполняется по одной,
  без параллельных merge в одну ветку.
- **VCS-платформа первой — GitHub (Q4, утверждено 2026-09-22)**: первый VCS Provider —
  GitHub. Контракт адаптера нейтрален к платформе: реализации GitHub и GitLab подключаются
  конфигурацией — в зависимости от задачи/продукта. GitLab (примеры Notion: `small.vcs-gitlab`,
  GitLab CI/MR) — второй целевой provider.

## Последствия

- GitHub и GitLab — взаимозаменяемые реализации одного контракта VCS Provider; ядро
  без изменений, выбор платформы — конфигурация задачи/продукта.
- Автономность merge ограничена и аудируется; отказ любого из 5 условий уводит решение
  к человеку (`decision_required`).
