# ADR-0010: Плагины и точки расширения

## Статус

Принято (инициализация репозитория, 2026-09-22).

## Основание

Notion v4: [«Модульность, декларативность и плагинная архитектура фабрики» (стр. 12)](../sources/notion-v4/12-plugins.md);
анализ §5.

## Контекст

Фабрика расширяется (адаптеры, наблюдение, инструкции), но расширения не должны получать
власть над конвейером. Нужны уровни расширений, границы доверия и минимальный API.

## Решение

- **Два уровня плагинов**: уровень фабрики (`plugins/factory/`) и уровень DSH
  (`plugins/dsh/` — только при подтверждённом пробеле SDK).
- **Plugin API `factory.plugin/v1`**: манифест с полями `id` (namespaced), `entrypoint`,
  `requires`, `provides`, `configSchema`, `requestedPermissions`.
  `requestedPermissions` — **декларация, не выдача**: полномочия назначает composition root.
- **Порты плагинов**: плагины **не меняют таблицы ядра**, не выставляют `accepted`,
  не запускают следующий этап. Влияние на конвейер — только через контракты гейтов/инструкций.
- **Composition root**: единственное место сборки графа зависимостей и выдачи полномочий.
- **TypeScript-интерфейс — не граница безопасности** (см. ADR-0011): недоверенные плагины —
  вне процесса ядра.
- **Точки расширения MVP**:
  - `HarnessAdapter` — только DSH (ADR-0001);
  - VCS Provider — один контракт; реализация GitHub или GitLab по конфигурации,
    первый — GitHub (ADR-0006);
  - Delivery Provider — один;
  - Workspace Provider — worktree (MVP);
  - Instruction/Context Provider — spec-kit и файловые источники;
  - Observer — наблюдение за событиями ядра.
- **«Полные полномочия» = пересечение** декларации плагина и выданного доверия.

## Последствия

- Расширение фабрики не требует форка ядра, но и не даёт плагинам власть над гейтами.
- API версии `factory.plugin/v1` фиксирует совместимость манифестов (см. релиз-манифест,
  ADR-0009).
