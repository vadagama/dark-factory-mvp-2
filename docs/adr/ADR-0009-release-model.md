# ADR-0009: Релизная модель фабрики

## Статус

Принято (инициализация репозитория, 2026-09-22).

## Основание

Notion v4: [«Разработка, версионирование и откат релизов фабрики на DSH» (стр. 11)](../sources/notion-v4/11-releases.md),
[«Модульность, декларативность и плагинная архитектура фабрики» (стр. 12)](../sources/notion-v4/12-plugins.md);
анализ §5, §7; заменяет ADR-056
(имя репозитория — по Q8: `dark-factory-mvp-2`).

## Контекст

Фабрика сама — продукт, который нужно поставлять и откатывать предсказуемо. Нужен
неизменяемый артефакт релиза и порядок развития MVP.

## Решение

- **Неизменяемый релиз-комплект с манифестом**: `factoryVersion, sourceCommit,
  artifactDigest, dshVersion, dependencyLockDigest, processPackDigest, knowledgeCommit,
  stateSchemaVersion, harnessContractVersion, rollbackPolicy`.
- **Launcher**: `df release install / activate / status / rollback`; один номер версии на
  весь комплект.
- **Кандидат изолирован**: релиз-кандидат устанавливается и проверяется параллельно
  активной версии до активации.
- **Откат = возврат артефакта** (предыдущий комплект), не пересборка.
- **Откат программы ≠ откат действий/данных**: выполненные внешние действия и изменения
  продуктовых репозиториев не отменяются откатом фабрики.
- **Стадии развития MVP** (каждая — поставка):
  1. **0.1 Исполнение** — ядро + DSH-адаптер, Attempt/StageRun, CLI start/status.
  2. **0.2 Процесс** — декларативный процесс, гейты, доработка (ADR-0004/0005).
  3. **0.3 Разработка** — маршруты SDD/BugFixing/Assessment через Spec Kit (ADR-0007).
  4. **0.4 Релизы** — комплект/launcher/откат.
  5. **0.5 Параллельность** — лимиты попыток, очереди интеграции.
  6. **0.6 Доставка** — DeliveryAdapter, merge/delivery-гейты (ADR-0006).
- **Monorepo `packages/*`** — единый репозиторий ядра; отдельные репозитории
  (`dark-factory-knowledge`, `dark-factory-gitops`) — позже, по потребности.

## Последствия

- Воспроизводимость: манифест фиксирует все слои (код, DSH, зависимости, процесс, знание).
- Государство состояния (`stateSchemaVersion`) мигрирует явно — совместимость БД
  контролируется launcher'ом.
