# ADR-0012: Переносимые решения v1 (Q4, Q6, Q7, Q9, Q10)

## Статус

Принято (инициализация репозитория, 2026-09-22).

## Основание

Анализ `docs/analysis/2026-09-22-init-architecture-comparison.md` §4 (Q4, Q6, Q7, Q9, Q10,
Q11); ADR-019, ADR-023, ADR-058 v1 по смыслу;
Notion v4: [«Архитектура v4» (SMALL-контекст, гейты, контракт DSH)](../sources/notion-v4/00-index.md).

## Контекст

Часть решений v1 не вошла в текст Notion v4, но согласуется с ним. Чтобы конвейер был
полным, они фиксируются здесь; каждое может быть пересмотрено отдельным ADR/amendment.

## Решение

- **Q4 — VCS-first: GitHub (утверждено 2026-09-22).** Первый VCS Provider — GitHub; контракт
  адаптера нейтрален к платформе: GitHub или GitLab подключаются конфигурацией в зависимости
  от задачи/продукта. GitLab — второй целевой provider (примеры Notion: `small.vcs-gitlab`,
  GitLab CI/MR). Детали — ADR-0006.
- **Q6 — OKF-слой не переносится.** Вместо канонического OKF — `baseline/` рядом с кодом,
  `.factory/product.yaml`, `baseline-impact.md`, фронтматтер, гейт согласованности.
  `factory-okf` — по потребности после пилота. Детали — ADR-0007.
- **Q7 — DecisionPort отложен.** Семантического decision-слоя нет: решения проходят через
  `Question`/`submit-decision` и политики риска. Вернуться после пилота.
- **Q9 — риск-классы R0–R3 переносятся.** Класс изменения/поставки определяет политику:
  `R0` — безопасные автономные merge/доставка; `R1` — автономный merge, доставка с
  подтверждением; `R2` — merge с подтверждением человека; `R3` — только ручные решения.
  Политики риска — в гейтах (ADR-0005/0006), значения по умолчанию уточняются на 0.3+.
- **Q10 — механики DSH внутри попытки переносятся как hints.** Механики ADR-058 v1
  (подсказки исполнения попытки) передаются в `HarnessRequest.limits/policy` при
  поддержке `HarnessCapabilities`; сверить с фактическим SDK на этапе 0.1.
- **Q11 — must-keep v1 (11 принципов) переносятся** текстом ADR-0001…0011
  (распределение — см. §5 анализа).

## Последствия

- Ни одно из решений не зашито в ядро: VCS/риск/hints — конфигурация и адаптеры.
- Изменение любого пункта — новый ADR или amendment с указанием мотивации.
